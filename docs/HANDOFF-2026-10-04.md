## 1. המעבר: המק דוחף ישירות

> **בוצע ב-4.10.2026, אחרי כתיבת המסמך.** הריפו שובט מ-GitHub אל `~/Code/yakircohen-site`, המק דוחף משם, וווינדוס לא דוחף. ה-`.git` שב-Dropbox פגום ולא דחפו ממנו. הכללים המעודכנים ב-`AGENTS.md`.

### למה זה נדרש

היום ה-`.git` עצמו מסונכרן ב-Dropbox בין המק ל-PC, והמק אינו דוחף.
קומיט שנוצר במק מגיע ל-PC דרך Dropbox, וה-PC דוחף.

**המחיר נמדד ב-4.10:** שלוש דחיפות נכשלו ברצף כי ה-PC קרא `.git` ישן.
בפעם הרביעית התברר שהעיכוב היה 14 אובייקטים ו-97KB שהמתינו לסנכרון,
ושקובץ ה-index של ה-PC דרס את זה של המק שעה אחרי הקומיט והחזיר מצב
קונפליקט מדומה. יש גם 10 עותקים מתנגשים של `.git/index` בתיקייה.

### מה כבר קיים במק

| | |
|---|---|
| `credential.helper` | `osxkeychain`, כבר מוגדר |
| `gh` CLI | לא מותקן |
| מפתחות SSH | אין |
| remote | HTTPS, `github.com/callwebboss-bit/yakircohen.com.git` |

כלומר הדרך הקצרה היא טוקן, בלי להתקין כלום.

### הצעדים

1. ב-GitHub: **Settings** → **Developer settings** → **Personal access
   tokens** → **Tokens (classic)** → **Generate new token (classic)**
2. לסמן את ההרשאה **`repo`** בלבד. לתת תוקף, ולשמור את הטוקן בצד
3. במק, בתיקיית הריפו, לדחוף פעם אחת:

   ```bash
   git push origin preview/chrome-polish:main
   ```

4. git יבקש שם וסיסמה. **שם:** `callwebboss-bit`.
   **סיסמה:** הטוקן, לא סיסמת GitHub
5. `osxkeychain` ישמור אותו, ומכאן והלאה הדחיפה עובדת בלי שאלות

### אחרי שזה עובד, שני דברים לסגור

**א. לעדכן את `AGENTS.md`.** הוא אומר היום במפורש "אין הרשאות GitHub.
לא לנסות `git push`" ו"ווינדוס הוא הפורס הבלעדי". כל סוכן קורא את זה
ומסרב לדחוף. אחרי המעבר זה שקר, והוא ימשיך להטעות.

**ב. לשקול להוציא את הריפו מ-Dropbox.** זה התיקון העמוק. Dropbox
השחית בנייה פעמיים, יצר 10 עותקים מתנגשים של `.git/index`, וגורם
לעיכובים. `node_modules` ו-`.next` כבר מוחרגים, אבל `.git` לא.
**לא לעשות בלי אישור הבעלים:** זו הזזה של עץ עבודה שסוכנים אחרים

## 4. החלטות הבעלים, ומה נשאר מהן

ארבע הוכרעו מול הבעלים ב-4-5.10. שלוש בוצעו, אחת נמסרה לענף אחר.

### א. דירוג גוגל. הוכרע: הענף השני מביא את זה

`lib/constants.ts` הצהיר `GOOGLE_RATING = "4.9"`, בזמן שב-`feature/sales-fix`
הבעלים אישר ב-4.10 דירוג **5.0**. **ההחלטה: לא לגעת כאן**, כדי לא ליצור
קונפליקט כפול.

**אזהרה למי שימזג:** הבדיקה ב-`lib/constants.test.ts` **תעצור את המיזוג**
עד שתתווסף רשומת מקור ל-"5.0 ★" ב-`TRUST_CLAIM_SOURCES`. זה מכוון.
לעדכן את הרשומה, לא לעקוף את הבדיקה.

### ב. מספרי אמון. בוצע

נוסף `TRUST_CLAIM_SOURCES`: כל מספר אמון מוצג חייב מקור, מי אישר ומתי,
ואסור שתישאר רשומה בלי מספר תואם.

הנוסח הראשון היה שער חסר ערך: הרשומות נכתבו כ-`${GOOGLE_RATING} ★`, ולכן
זזו יחד עם הקבוע. נמדד ששינוי הדירוג ל-5.0 עבר בירוק. תוקן לערכים קבועים,
ואומת ששינוי הדירוג או מספר הביקורות מפיל שלוש בדיקות.

**נסגר 5.10.2026: "5,000+ לקוחות"** הוא הערכת הבעלים על בסיס היקף
העבודה לאורך השנים, לא ספירה ממערכת, בלשונו "פלוס מינוס, מספר אפשרי
ואפילו שיש יותר". ה-`+` מסמן רצפה. מתועד ב-`TRUST_CLAIM_SOURCES`.

**תיקון להנחה שהופיעה כאן קודם:** נכתב שמספרי האמון נכנסים ל-JSON-LD.
נבדק בפלט הבנוי ואין זה נכון: האתר **לא מפרסם `aggregateRating` כלל**,
אפס עמודים, ואין לכך זכר בקוד. שלושת המספרים הם קופי גלוי בלבד. השער
עדיין שימושי, כי מספר שגוי שגולש קורא פוגע באמון, אבל הסיכון קטן ממה
שתואר.

### ג. `/business/professional-voiceover`. בוצע

ה-h1 היה "קריינות מקצועית" והתחרה ב-h1 של `/voiceover`. הגוף, הכותרת,
ה-CTA וכפתור השיתוף כבר אמרו "קריינות לסט DJ". תוקן.

### ד. שישה מקרי בוחן. בוצע: הוסרו

`lib/data/site-case-studies.ts` נשא הערה משלו, "עובדות מהשטח. עדכן מספרים
לפי פרויקטים אמיתיים", כלומר מספרי תבנית. הם הוצגו תחת הכותרת "דוגמאות
מהשטח" בדף הבית, `/studio`, `/events`, `/podcast` ו-`/shop`, עם נתונים
כמו "כ-180 אורחים, 5 שעות הפעלה".

**הבעלים אישר 5.10 שאלה אינם פרויקטים אמיתיים והורה להסיר.** הוסרו חמשת
השיבוצים, הקומפוננטה וקובץ הנתונים. ההיסטוריה שומרת אותם.

**הבעלים מוסיף תיק עבודות אמיתי לכל האתר.** כשהוא יגיע, זה המקום שבו

## 7. איך מוודאים שלא נשבר כלום

```bash
npm run deploy:status     # ראשון תמיד. קורא בלבד
npm run verify:seo        # 24 שערים
npx tsc --noEmit
npm run lint
npm run build:full
npm run audit:seo-diff    # חוסם גריעת אות סורקים
```

`audit:seo-diff` נכשל גם על **אישור מת**, כלומר אישור שלא תאם שום
הבדל. זה מכוון: אישור מת משתיק בדיקה. אם הוא נכשל כך, למחוק את
הרשומה, לא להוסיף עוד אחת.

**כלל שנלמד ב-4.10:** לפני שבונים שער או מחולל, להריץ `git fetch`
ולהשוות את הקובץ מול `origin/main`. בניתי הקשחה ל-`sync-llms.ts`
במקביל לסוכן אחר שבנה בדיוק את אותו מנגנון, והעבודה שלי נזרקה.
