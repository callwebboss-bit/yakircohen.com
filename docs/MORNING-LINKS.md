# לינקים לתשלום במורנינג: הנוהל

עודכן 12.10.2026 (גרסה 3 של התוכנית, אחרי פרה-מורטם). ההחלטות: הלינק רק בדלפק `/admin/sales`; הלינק הוא ההודעה השלישית (אחרי ההודעה ו"רק לוודא"); ברירת מחדל קצרה; מקדמה 200 ₪ רק באישור יקיר; תיאור הפריט במורנינג קצר ומפנה ל-/whats-included; ה-API של מורנינג בכתיבה בלבד מהמחשב של יקיר; מדד: 10 תשלומים בלינק בחודש הראשון.

- [ ] **0.3 הלקוח בטלפון** (יקיר, 10 דק): לינק ניסיון "הקלטת שיר" 590 ₪ במורנינג, פתיחה מהטלפון כלקוח עד מסך האשראי, בלי לשלם. לספור: שדות חובה, לחיצות, מה כתוב, האם יש שדה הערה (לקוד פנייה).
- [ ] **1 שבוע עם שני לינקים** (יקיר): לינק "הקלטת שיר" + לינק סכום פתוח (7 סכומים קבועים מהגיליון `docs/morning-links-sheet.md`). שמירה: `npm run morning:link -- --id song_recording --url ...` ו-`--id open --url ...`. בסוף השבוע: כמה נשלחו, כמה שולמו, מה שאלו.
- [ ] **4 פריטים ופירוט** (רק אחרי השבוע): 20 כרטיסים נוספים עם "כלול/לא כלול" בשאלונים, ואז `npm run morning:sync` (ייכתב אחרי שלב 0).

## מה יש בדלפק היום

לכל כרטיס אזור "לינק לתשלום":
- הכפתורים אפורים עד שהעתקת "הודעה" או "רק לוודא" באותו כרטיס (הלינק הוא ההודעה השלישית).
- **העתק הודעה עם לינק** (קצרה): `לתשלום על {שירות}, {סכום} כולל מע״מ: {לינק}` + "אחרי התשלום החשבונית מגיעה למייל אוטומטית."
- **עם הפירוט**: + "כולל a, b, c. לא כולל d, e." מהקטלוג, עד 350 תווים, הלינק תמיד נשאר.
- **או בהעברה**: מופיע רק אחרי `npm run morning:link -- --bank "הטקסט שלך"` (בלי מספר חשבון בקוד; מה שתכתוב זה מה שיישלח).
- **רק הלינק**, **התשלום לא עבר?** ("קורה לפעמים. נסו שוב בלינק הזה, או בהעברה, ואני מאשר מיד").
- **מקדמה (רק באישור יקיר)**: קישור קטן שפותח את "העתק לינק מקדמה 200 ₪". ההודעה: "מקדמה של 200 ₪ לשמירת התאריך, היתרה לפי ההצעה".
- **שדות ללינק קבוע במורנינג**: מה להקליד כדי ליצור לינק לשירות הזה. התיאור: "{שירות}. התנאים: yakircohen.com/whats-included".

## פקודות

| פקודה | מה |
|---|---|
| `npm run morning:api -- --whoami` | טוקן + שם העסק. בלי להדפיס טוקן |
| `npm run morning:api -- --probe-links` | האם יש API ללינקים (A/B/C) |
| `npm run morning:api -- --items-search` | האם פריטים נתמכים |
| `npm run morning:api -- --probe-form` | דף תשלום לעסקה על 1 ₪, רק כדי לראות url. לא לשלם |
| `npm run morning:link -- --id <מזהה> --url <לינק>` | שומר לינק קבוע (או `deposit` / `open`) |
| `npm run morning:link -- --id <מזהה> --price <סכום>` | אחרי עדכון המחיר בלינק במורנינג |
| `npm run morning:link -- --bank "..."` | שורת "או בהעברה" |
| `npm run morning:link -- --remove <מזהה>` | אחרי הקפאת לינק במורנינג |
| `npm run morning:link -- --list` / `--check` | מצב; `--check` רץ ב-audit:pricing |
| `npm run morning:sheet` | `docs/morning-links-sheet.md`: מה להקליד במורנינג |
| `npm run morning:checklist` | `docs/morning-checklist.html`: עמוד המצב שעובדים איתו |

## שינוי מחיר (סדר הפוך)

קודם עורכים את הלינק במורנינג לסכום החדש (ה-URL נשאר, מדריך "עריכת לינק לתשלום"), ואז מעלים את המחיר בקטלוג ומריצים `npm run morning:link -- --id <מזהה> --price <הסכום>`. ככה אין חלון שבו לקוח משלם מחיר ישן. `audit:pricing` נכשל אם שכחת.

## מה עוד לא נבנה (תלוי בשלב 0)

- מסלול A: הדלפק קורא את הלינקים ממורנינג, אין קובץ. מסלול B/C: שדה "הדבק לינק" בכרטיס שכותב ל-Redis, בלי טרמינל.
- `morning:status`: לינקים מתים, מחיר/פירוט שזז, תשלומים חדשים, פעם ביום לוואטסאפ של יקיר.
- webhook "תשלום התקבל" -> הליד מסומן "שולם" (D22) + וואטסאפ ליקיר עם סכום וקוד פנייה בלבד.
- `morning:sync`: פריטים במורנינג מהקטלוג (sku = מזהה, מחיר כולל מע״מ, תיאור קצר).

## כללים

- הסכום בלינק תמיד כולל מע״מ, גם לעסקים. אין מספרים בהודעות שלא מהכרטיס. עד 350 תווים, בלי סימני קריאה (audit:ai-tells).
- הקובץ `lib/data/morning-links.json` מכיל רק URL-ים ציבוריים של מורנינג (greeninvoice.co.il, morning.co, grow.co.il, meshulam.co.il), בלי מפתחות.
- הלינק ללקוחות חדשים ורחוקים (אולפן נייד, מתנות, עסקים). לא דוחפים העברה בנקאית לאשראי: עמלה 1.4% + 1.2 ₪ לעסקה (Best), bit +0.3% (greeninvoice.co.il/payment-links, 11.10.2026).
- מורנינג: אחרי תשלום בלינק המסמך (חשבונית מס-קבלה או קבלה) מופק ונשלח ללקוח במייל אוטומטית. לינקים לתשלום דורשים Best ומעלה וסליקה פעילה (יש).
