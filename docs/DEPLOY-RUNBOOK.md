## 0. קודם לשמור, רק אחר כך לבנות

הסדר כאן מכוון. **הבנייה יכולה להיכשל. שמירה ב-git לא.** ברגע שהעבודה ב-git,
שום כשל בנייה ושום סוכן לא יכולים לאבד אותה. לכן שומרים לפני שבונים.

```bash
cd yakircohen-site

# 1. לוודא ש-Dropbox הביא את כל 272 הקבצים בשלמותם
node scripts/change-manifest.mjs --verify

# 2. לשמור. עכשיו. לפני npm ci, לפני build, לפני כל דבר.
git add -A
git commit -m "סבב שיפורים ספטמבר 2026: 410 לשרידי החנות, פוטר סריק, לידים, נגישות"

# 3. עכשיו אפשר להתקין ולבנות בלי חשש
rm -rf node_modules
npm ci
node scripts/preflight-deploy.mjs
```

**`change-manifest --verify`** משווה את תוכן כל קובץ (hash) מול חותם שנוצר בסוף
העבודה. אם Dropbox לא סינכרן קובץ, או שמישהו שחזר משהו, הוא אומר בדיוק מה.
`docs/CHANGE-MANIFEST.md` מפרט את כל 272 הקבצים בקריאה אנושית.

**`preflight-deploy`** בודק את הכשלים שנראים סתומים כשהם קורים בענן, ומדפיס לכל
ממצא גם **למה** וגם **תיקון**. אחרי ה-commit הוא אמור להתלונן רק על esbuild
(שנפתר ב-`npm ci`) ואולי על משתני סביבה.

הוא גם בודק מול oEmbed שכל סרטוני היוטיוב באתר עדיין חיים (`scripts/check-videos.mjs`,
כ-10 שניות ודורש רשת). סרטון שמחזיר 401 (הטמעה חסומה) או 404 (נמחק או פרטי) חוסם את
הפריסה. תשובה לא חד-משמעית של יוטיוב, כמו 429 או חוסר רשת, רק מזהירה.
`--skip-videos` מדלג על הבדיקה.

> **אם תבחרו לשמור קובץ-קובץ במקום `git add -A`:** יש 18 קבצים שקוד שכן נמצא
> ב-git תלוי בהם, ותשעה מהם הם סקריפטים ש-`verify:predeploy` מריץ, כולל
> `preflight-deploy.mjs` עצמו. קובץ אחד שנשכח מפיל את הפריסה בהודעת
> `Cannot find module`, שנראית כמו תקלת npm ולא כמו קובץ חסר.
> **לפני ה-commit הריצו `node scripts/preflight-deploy.mjs`** והוא ינקוב בשם
> כל קובץ חסר ובפקודת ה-`git add` המדויקת שלו.

הקומיט הזה הוא על ענף `preview/chrome-polish`. הוא **לא** מעלה כלום לאוויר.
זו רק שמירה. הפריסה קורית במיזוג ל-`main`, בסעיף 1.

   (`/`, `/studio`, `/book`, `/podcast`, `/contact`), ו-axe על שישה.
   זו הפעם הראשונה שיש מספרים אמיתיים, כי כל האימות עד כה היה סטטי.

את כתובת התצוגה המקדימה שולחים לסוכן ההכנה, והוא מריץ עליה את המדידות.

```bash

```

מיזוג ל-`main` הוא החלטה שלכם. אל תשנו את הגדרת Production Branch ב-Vercel
כדי לעקוף את זה, ה-DEPLOY.md אוסר את זה במפורש.

## 3. אחרי הפריסה - אימות

הריצו את אלה מול הדומיין החי. הפלט המצופה כתוב מתחת לכל אחד.

### 3.1 ה-410 עובד

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://yakircohen.com/product/anything
curl -s -o /dev/null -w "%{http_code}\n" https://yakircohen.com/product-tag/x
curl -s -o /dev/null -w "%{http_code}\n" https://yakircohen.com/wp-admin
```

מצופה: **410** בשלושתם.

> שימו לב: בלי לוכסן בסוף. כתובת שמסתיימת בלוכסן מקבלת קודם 308 להסרתו
> (זה קורה בשלב ה-redirects, לפני ה-proxy), ואז 410. שתי קפיצות, שתיהן תקינות.
> אם תבדקו עם לוכסן ותראו 308, זו התנהגות נכונה ולא תקלה.

- **קיבלתם 301 או 308** - ה-proxy לא רץ. או שהמיזוג ל-`main` לא קרה, או ש-Cloudflare
  מגיש 301 מהמטמון. ראו 4.1.
- **קיבלתם 404** - ה-matcher לא תפס. בדקו ש-`proxy.ts` נמצא בשורש הריפו (לא ב-`src/`).
- **קיבלתם 200** - נורא. משהו שם מגיש עמוד אמיתי. `git revert` מיידית לסעיף 1.

### 3.2 שום דבר חי לא נשבר

```bash
for p in / /studio /events /podcast /pricing /shop /events/bar-mitzvah /blog; do
  printf "%-28s %s\n" "$p" "$(curl -s -o /dev/null -w '%{http_code}' https://yakircohen.com$p)"
done
```

מצופה: **200** בכולם. `/events/bar-mitzvah` הוא העמוד החדש.

### 3.3 קישורי הפוטר מגיעים לגוגל

```bash
curl -s https://yakircohen.com/ | grep -o 'href="/studio/[^"]*"' | sort -u | wc -l
```

מצופה: **מספר דו-ספרתי**. לפני השינוי זה היה 1 עד 2.
אם קיבלתם 1 או 2, ה-`forceMount` לא עבד ושווה לבדוק אם גרסת Radix השתנתה ב-`npm ci`.

### 3.4 מפת האתר עם תאריכים

```bash
curl -s https://yakircohen.com/sitemap.xml | grep -c "<lastmod>"
```

מצופה: **מספר זהה למספר הכתובות במפה** (334 ב-7.10.2026, כולל 4 כתובות `/online/*`
ו-7 עמודי קטגוריית בלוג שלא היו להם תאריך קודם). לפני כן זה היה בערך 316.
אם קיבלתם בערך 102, רק הבלוג וקטגוריות הבלוג מתוארכים (הם לא תלויים ב-JSON), והקובץ
`lib/data/sitemap-dates.generated.json` לא נכנס ל-git או שהוא ריק. ראו 4.2.

### 3.5 IndexNow

```bash
KEY=$(grep -oE '[0-9a-f]{32}' app/api/indexnow/route.ts | head -1)
curl -s https://yakircohen.com/$KEY.txt
```

מצופה: המפתח עצמו מוחזר כטקסט.
**המפתח הוחלף בסבב הזה** (הישן היה `a1b2c3d4...`, ניתן לניחוש). Bing יצטרך לאמת
מחדש. זה תקין ואמור להסתדר לבד תוך ימים.

### 3.6 הסכמה שגוגל מקבלת

```bash
curl -s https://yakircohen.com/ | grep -o '"price": *"[0-9]*"' | sort -u | head
```

מצופה: מחירים שקיימים ב-`lib/data/pricing-catalog.ts`.
**רקע:** לפני הסבב הזה האתר פרסם לגוגל הצעה של 1,800 ש״ח להקלטת שיר, בזמן
שהמחיר האמיתי הוא 990 והמספר 1,800 לא קיים בקטלוג כלל. הקובץ יוצר רק ב-Vercel
ולכן הגרסה השמורה התיישנה. `npm run audit:schema-prices` שומר על זה מעכשיו.

### 3.7 טופס ליד מקצה לקצה

זו הבדיקה החשובה ביותר, ואי אפשר לעשות אותה ב-curl. שלחו ליד אמיתי דרך `/book`
וודאו שהמייל הגיע.

**אם לא הגיע:** בדקו ב-Sentry תג `route: lead-intake`. השינוי בסבב הזה הוסיף דיווח
לכשלים שקודם נעלמו בשקט, כולל המקרה של "הליד נשמר אבל המייל נכשל". קודם התשובה
הייתה תמיד הצלחה, גם כשהמייל לא יצא.

## 4. תקלות נפוצות, לפי סדר סבירות

### 4.1 Cloudflare מגיש את ההפניות הישנות מהמטמון

**זו התקלה הכי סבירה בפריסה הזו.** שינינו 301 קבועים ל-410. 301 הוא קבוע מעצם
הגדרתו, ולכן גם Cloudflare וגם דפדפנים שמרו אותו.

```
Cloudflare → Caching → Configuration → Purge Everything
```

בלי זה תמשיכו לקבל 301 ותחשבו שהשינוי לא עבד. גם הדפדפן שלכם שמר, אז בדקו
בחלון פרטי או ב-curl.

### 4.2 מפת האתר בלי תאריכים

`scripts/generate-sitemap-dates.mjs` מושך תאריכים מהיסטוריית git. **Vercel משכפל
רדוד (עשרה קומיטים).** לכן הוצאתי אותו במכוון מ-`vercel-build`, והקובץ אמור להיות
מיוצר מקומית ולהיכנס ל-git.

התאריך של עמוד נלקח מהקומיט האחרון שנגע ב-`page.tsx` שלו **או בקבצי התוכן הפרטיים
שהוא מייבא** (`components/seo/*PageContent.tsx`, `lib/data/*-page.ts`). מודול שמשרת
יותר משלושה עמודים (מחירון, `services.ts`) לא נספר, אחרת כל עדכון מחיר היה מסמן
עשרות עמודים כמעודכנים. בלוג וקטגוריות הבלוג מתוארכים ב-`app/sitemap.ts` משדות
התאריך של הפוסטים (`dateModified`, אחרת `datePublished`), כי כולם יושבים בקובץ אחד.

כש-git לא זמין או שהשכפול רדוד, הסקריפט מזהה זאת, מזהיר, ושומר את התאריכים שכבר
ב-JSON (בתוספת קבועי `*_UPDATED_AT` של עמודי `/data/*` אם הם מאוחרים יותר). בשכפול
רדוד `git log` לא נכשל אלא נותן לכל הראוטים את תאריך קומיט הגבול, ולכן הזיהוי הוא
לפי `git rev-parse --is-shallow-repository` ולא לפי הכיסוי.

הסקריפט נכשל בכוונה אם הכיסוי הסופי יורד מתחת ל-80%, כדי שלא ידרוס נתונים טובים
בריקים. אם הוא נכשל אצלכם:

```bash
git fetch --unshallow
npm run generate:sitemap-dates
```

### 4.3 הבנייה נופלת ב-Module not found

כמעט תמיד קובץ שלא נכנס ל-git. `node scripts/preflight-deploy.mjs` מדפיס את
הרשימה המדויקת עם פקודת ה-`git add`.

### 4.4 `tsx` או `npm test` נופלים

`node_modules` הותקן על מערכת הפעלה אחרת. הריפו יושב ב-Dropbox ומסונכרן בין
מכונות, וזה קורה הרבה.

```bash
rm -rf node_modules && npm ci
```

אם אין אפשרות להתקין מחדש כרגע, אפשר להריץ את חבילת הבדיקות בלי tsx:

```bash
npm run test:notsx
```

Node 22 מפשיט טיפוסים בעצמו, ולכן הדבר היחיד ש-tsx נתן כאן היה פתרון מודולים.
`scripts/test-runner/` מחליף אותו. מצופה: 192 מתוך 193 עוברות. הכישלון היחיד הוא
`lib/api-guard.test.ts`, שמייבא `next/server` ולכן דורש את הפותר של Next עצמו.

### 4.5 אני מחובר ל-/admin ופתאום נזרקתי החוצה

צפוי וחד פעמי. הקוקי החזיק קודם את `ADMIN_LEADS_TOKEN` עצמו, ועכשיו הוא מחזיק
נגזרת HMAC. הקוקי הישן כבר לא תקף. פשוט להתחבר שוב באותו מפתח.

**למה שינינו:** הסוד הוא גם `Authorization: Bearer` תקף מול
`/api/admin/leads/export`, ולכן קוקי שדולף היה מוסר גישה מלאה לכל מסד הלידים.

### 4.6 CI נכשל על `audit:a11y`

**זה מצב קיים מלפני הסבב הזה, לא רגרסיה.** `.github/workflows/ci.yml` מריץ את
האודיט **לפני** הבנייה ובלי שרת שרץ, ובלי להתקין דפדפן. גם כשהוא "עובר" הוא בדק
אפס עמודים. זה מטופל בשלב 4 של התוכנית.

### 4.7 חיפוש באתר לא עובד

`vercel-build` מריץ Pagefind. אם Build Command ב-Vercel הוגדר ידנית ל-`next build`
במקום להישאר ריק, האינדוקס לא נוצר.

## 6. התשתית

הוצא מ-`vercel-build` והקובץ שהוא מייצר נשמר ב-git במקום להיווצר שם.

## 7. סקריפטים שמסוכן להריץ בטעות
