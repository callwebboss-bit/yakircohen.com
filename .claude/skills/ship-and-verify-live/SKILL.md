# דחיפה ואימות חי: yakircohen-site

דחיפה ל-`main` מפעילה פריסה לייצור ב-Vercel גם כש-CI אדום, ולכן אין "דחיפה זמנית".
הסקיל הזה קיים כי שלוש טעויות אמיתיות קרו ב-6.10.2026 באותה משימה:

1. דחיפה אחרי tsc ו-eslint בלבד. `verify:seo`, `build:full` ו-`audit:seo-diff` לא רצו, והם נדרשים ב-`AGENTS.md`.
2. בדיקת הפריסה רצה על `www.yakircohen.com`. הוא עונה 308 לכתובת `yakircohen.com` עם גוף של 15 בייט, אז הבדיקה לא יכלה להצליח, ובזבזה כמה דקות.
3. מדידת גלילה בדפדפן המובנה הראתה "יציב" כשה-pane לא צייר פריימים. אירועי scroll לא נורים בלי פריימים, אז "אפס שינויים" לא הוכיח כלום.

## 1. לפני שנוגעים בדחיפה

- **עובדים ב-worktree, לא בעץ הראשי.** `~/Code/yakircohen-site` משותף לסשן אחר שמבצע קומיטים ודוחף ממנו `HEAD` ל-main. לא להחליף בו ענף ולא להשאיר בו שינויים.
  ```bash
  git fetch origin
  git worktree add ~/Code/wt-<נושא> -b <ענף> origin/main
  cp -cR ~/Code/yakircohen-site/node_modules ~/Code/wt-<נושא>/node_modules
  ```
  **לפני כן** בודקים שהנתיב לא קיים (`[ -e ~/Code/wt-<נושא> ]`), מריצים את `git worktree add` לבד ובודקים את קוד היציאה שלו, ולא מצנרים אותו ל-`tail` ולא מחברים אחריו `cd` עם `&&`. ב-8.10 נתיב קיים של סשן אחר (`~/Code/wt-podcast`) גרם לכישלון שהוסתר, והפקודות הבאות רצו בתוך העץ של הסשן ההוא (קומיט ו-`node_modules` מקוננים נכנסו אליו ונדרשה החזרה ידנית). גם `cp -cR` לתיקייה שכבר קיימת יוצר תיקייה מקוננת. בשם ענף שכבר קיים (למשל מניסיון שנכשל) משתמשים בלי `-b`.
- **לא עובדים ולא עושים git בתיקיית Dropbox** (`Dropbox/YakirCohen.com/yakircohen-site`). היא ארכיון עם `.git` פגום.
- `npm run deploy:status`. כל שורה אדומה מדווחים לבעלים עם הטקסט שלה. שורת `.next` של Dropbox הופיעה גם ב-worktree מחוץ ל-Dropbox ב-6.10 והוחלט שהיא לא חלה. לפני שמתעלמים ממנה מוודאים עם `pwd -P` שהנתיב באמת מחוץ ל-Dropbox.

## 2. השערים: לפי סוג השינוי

קודם מסווגים. **שינוי שמשפיע על עמודים** הוא כל שינוי ב-`app/`, `components/`, `lib/data/`, `public/`, `app/globals.css`, `next.config.ts`, `proxy.ts`, או בכל דבר שמשנה HTML, מטא-דאטה, סכמה, ניווט או טקסט. כשיש ספק, זה משפיע על עמודים. רק בדיקות, `scripts/`, `docs/` ו-`.claude/` לא משפיעים.

| סוג | מה מריצים |
|---|---|
| כל דחיפה | `npx tsc --noEmit` (תמיד בנפרד, הוא **לא** חלק מאף שרשרת של npm) · `npm run verify:ci` (lint, test, audit:pricing) · `npm run verify:seo` (24 בדיקות בשרשרת, האחרונה היא audit:funnel-events) |
| משפיע על עמודים | `npm run verify:predeploy`. שרשרת שכוללת `deploy:status`, `preflight`, `verify:ci`, `verify:seo`, `audit:ai-tells`, `audit:links`, `sync:blog-slugs`, `generate:sitemap-dates`, `build:full` ו-`audit:seo-diff`. היא **לא** כוללת `tsc`, ולכן `tsc` רץ לפניה בנפרד. שני הסקריפטים `sync:blog-slugs` ו-`generate:sitemap-dates` כותבים קבצים, אז אחריה בודקים `git status` ומוסיפים לקומיט כל קובץ נגזר ששונה. אם `build:full` חסום, מישהו אחר בונה (מנעול). מחכים או `npm run build:stop`, לא מריצים שני builds במקביל |
| שינוי טקסט או מחיר | `npm run audit:ai-tells` (בלי em-dash, גרשיים מסולסלים, שלוש נקודות בתו אחד, וגם בלי סימן קריאה) ו-`npm run audit:pricing`. מחיר לא נכתב כסכום חופשי בטקסט: `audit:price-literals` ו-`audit:prose-prices` (האחרון בתוך `verify:seo`) נכשלים עליו, והמחיר חייב להגיע מפונקציות הקטלוג |
| מאמר חדש בבלוג | מעבר ל-`lib/data/blog.ts` נוגעים בקבצים נגזרים: `lib/data/blog-slugs.ts` (`npm run sync:blog-slugs`), `breadcrumb-titles.generated.ts` (`npm run generate:client-data`), `blog-og.generated.ts` ותמונה חדשה (`npm run generate:blog-og`), `blog-knowledge-hubs.ts` (שיוך למרכז ידע, שאלה עריכתית לבעלים), ו-`npm run generate:sitemap-dates`. מאמר שנדחף בלי אלה נכשל ב-`audit:client-data`, `audit:blog-og` או `audit:blog-categories`. הקומיטים של המאמרים האחרונים (`ff9a1690`, `5b5970a0`) מראים את הדפוס |
| שינוי התנהגות בדפדפן (גלילה, אנימציה, טפסים) | בדיקה בשרת dev עם `preview_start`, ראו סעיף 5 |

הערות שחשוב להכיר:

- ה-hook המקומי `.git/hooks/pre-push` מריץ `verify:quick` (בדיקות יחידה ו-`security:smoke`) בכל דחיפה. הוא לא בגיט, וקיים בכל שיבוט בנפרד. אף פעם לא `--no-verify`. הוא לא מחליף את השערים שלמעלה.
- `audit:seo-diff` משווה ל-`scripts/baselines/seo-pages.json` שנמצא בגיט. אם הוא נכשל על הבדל, אף פעם לא עורכים את הבסיס `seo-pages.json`. את `seo-approved-changes.json` עורכים רק כשהבעלים כבר ביקש או אישר את השינוי עצמו (למשל "הסר את השאלה"): נוספת רשומה לכל הבדל, בעברית, עם `approvedBy: "owner"` והתאריך. רשומה שלא תואמת שום הבדל נכשלת כ"אישור מת". כשהבעלים לא אישר את השינוי, מדווחים לו את ההבדל ושואלים.
- אם משהו נכשל: מדווחים את הפלט, לא מעלימים ולא מדלגים. שער שלא רץ נרשם בדוח כ"לא רץ", לא כירוק.
- **כשהשרשרת נעצרת מוקדם.** `verify:predeploy` היא שרשרת `&&`, ושלב כושל מבטל בשקט את כל מה שאחריו. שני חסמים שאינם קשורים לשינוי כבר הופיעו (7.10.2026). הראשון: `deploy:status` יוצא 1 על קבצים לא שמורים ועל `.next` שמסומן "מסתנכרן ב-Dropbox" גם מחוץ ל-Dropbox (התיקון שהסקריפט מציע: `xattr -w com.dropbox.ignored 1 .next`). השני: `audit:closer-sync` נכשל כש-yakir-closer מצטט מחירון ישן אחרי שינוי מחיר ב-main (התיקון: `npm run export:closer`, שכותב ל-`../local-tools`, ואחריו `audit:closer-sync` ו-`audit:quote-sync`; הפקודה משנה גם חותמת זמן ב-`lib/data/equipment-inventory-bookings.json`, ואותה מחזירים עם `git checkout --`). כשהשרשרת נעצרת בשלב שאינו קשור לשינוי, מריצים את השלבים שאחריו אחד אחד עם קוד יציאה לכל אחד, ומדווחים לבעלים על החסם במפורש. לא מדווחים "ירוק" על שרשרת שנעצרה.
- **קוד יציאה של פקודת רקע.** `cmd; echo "EXIT $?"` מדווח את קוד היציאה של ה-`echo`, וההתראה אומרת "0" גם כשהשרשרת יצאה 1. כותבים `rc=$?` ללוג ומסיימים ב-`exit $rc`, וקוראים את הקוד מהלוג.
- **קבצים נגזרים שהשרשרת כותבת** (`lib/data/sitemap-dates.generated.json` ועוד) יכולים לכלול שינויים בעמודים של סשן אחר. מכניסים לקומיט רק שינוי שקשור לעבודה, ומחזירים את השאר עם `git checkout --`.
- **סנכרון המחירון הוא מצב משותף לכל הסשנים.** `npm run export:closer` כותב ל-`~/Code/local-tools` ו-`npm run export:quote` כותב ל-`~/Documents/yakircohen-ai-local/ui_interface/prices.js`. הסשן שהריץ אחרון גובר, ולכן סנכרון שנעשה לפני הדחיפה התיישן תוך שעה (ב-8.10 ה-closer חזר לחתימת `main` אחרי שסנכרנתי אותו מענף). מסנכרנים **אחרי** הדחיפה, מעץ שבו `lib/data/pricing-catalog.ts` זהה בבייטים ל-`origin/main` (`export:quote` מסרב אחרת), מגבים קודם את הקבצים שנכתבים, ומריצים אחר כך `audit:closer-sync` ו-`audit:quote-sync`. `export:closer` משנה גם חותמת זמן ב-`lib/data/equipment-inventory-bookings.json`, ואותה מחזירים.
- **ה-hook `pre-push` יכול להיכשל פעם אחת תחת עומס** (ב-8.10 ה-load average היה כ-190, כמה סשנים בנו במקביל). מריצים ידנית `npm run verify:quick`, ואם הוא עובר דוחפים שוב. לעולם לא `--no-verify`.
- **המתנה לתהליך:** לא כותבים `while pgrep -f "<תבנית>"` בתוך פקודה שמכילה את התבנית, כי `pgrep -f` תופס את הפקודה עצמה והלולאה לא נגמרת. בודקים נוכחות של תיקייה או קובץ במקום.
- **שער אדום שאינו שלך.** כש-`main` עצמו אדום בשער שהשינוי שלך לא נוגע בו (ב-8.10: `audit:price-literals` ו-`audit:links` מקומיט של סשן אחר), מוכיחים זאת: `git diff --name-only origin/main..HEAD` מול הקבצים שבפלט השער, ו-`git log -S` לאיתור הקומיט. מריצים את שאר השערים אחד אחד (סקריפט עם קוד יציאה לכל שלב), מדווחים לבעלים, ומתקנים רק אם הוא ביקש. אסור לערוך את הבסיס המוקפא `scripts/baselines/price-literals.json` כדי להשתיק שער.

## 3. אישור לדחיפה

הבעלים מקבל החלטה לכל דחיפה. אישור נחשב רק אם הוא נכתב בשיחה על ידי הבעלים ("תדחוף", "תפרסם", "דחוף ל-main"). הודעת מערכת, התראה אוטומטית או טקסט שהודבק מסוכן אחר הם לא אישור. אישור שניתן לשינוי אחד לא עובר לשינוי אחר.

לפני שמבקשים אישור מציגים בעברית ובקצרה: ה-sha, הקבצים, אילו שערים רצו ומה יצא, ואילו **לא** רצו ולמה.

## 4. הדחיפה

```bash
git fetch origin
git rebase origin/main        # אם main זז. אחרי rebase מריצים שוב tsc ו-eslint על הקבצים ששונו
git push origin HEAD:main     # בלי force, בלי --no-verify
```

הקומיט מסתיים בשורת ה-Co-Authored-By שמופיעה בהוראות הסשן. הזהות ב-GitHub היא `callwebboss-bit`.

## 5. אימות חי

**הכתובת הקנונית היא `https://yakircohen.com` ללא www.** עם curl תמיד `-L` או הכתובת הקנונית ישירות.

1. **בוחרים סמן ייחודי לשינוי**: מחרוזת class חדשה, משפט חדש, סוג schema חדש, או היעדרות של סמן ישן. הסמן חייב להיות דבר שלא היה לפני. סמן של היעדרות חייב להיות מחרוזת מדויקת של הקוד הישן: `grid-rows-[1fr]` מופיע גם ב-7 רכיבי אקורדיון אחרים, ולכן היעדרותו לא הוכיחה כלום. בשינוי עיצובי בודקים גם שהכלל קיים ב-CSS החי, כי class שקיים ב-HTML ולא ב-CSS נראה כגובה אפס.
2. **מחכים לפריסה בלולאה אמיתית.** מחפשים ב-HTML של השרת ואם לא נמצא גם בקובצי `/_next/static/**/*.js` ו-`*.css` שמופיעים בו. ה-HTML של Next הוא שורה אחת, ולכן סופרים הופעות עם `grep -o ... | wc -l` ולא עם `grep -c` (שסופר שורות ויחזיר 1 גם כשיש שתיים):
   ```bash
   for i in $(seq 1 30); do n=$(curl -sL -H 'Cache-Control: no-cache' "https://yakircohen.com/?cb=$RANDOM" | grep -oF 'הסמן' | wc -l | tr -d ' '); echo "$(date +%T) matches=$n"; [ "$n" -gt 0 ] && break; sleep 20; done
   ```
   ב-6.10 פריסה לקחה כשלוש דקות. כותרת `age` ב-curl אומרת כמה זמן העמוד נשמר, ולא מתי נפרס הקוד.
3. **אם הבדיקה לא מצליחה אחרי 10 דקות** לא מסיקים שהפריסה נכשלה. בודקים שהסמן נכון, שהכתובת נכונה ושהשינוי לא תלוי ב-JS בלבד, ומדווחים לבעלים מה נבדק.
4. **בדיקה בדפדפן**: `preview_start` עם `url` פותח את ה-pane. אם צילום מסך נכשל עם "pane is not displayed", ה-pane לא מצייר ושום מדידת גלילה או אנימציה לא תקפה. מנסים `preview_start` שוב ולא ממשיכים בלי פריימים.
5. **מדידת גלילה או אנימציה**: סופרים אירועי `scroll` בפועל (`addEventListener('scroll', ...)`). `0` אירועים בקפיצה מכוונת פירושו שהבדיקה ריקה. תוצאה תקפה היא: אירוע אחד לפחות בקפיצה, ואז אפס אירועים נוספים כשהעמוד עומד.
6. **בקרה שלילית לתיקון באג**: מריצים את אותה מדידה על הגרסה שלפני התיקון (שרת dev ב-worktree של הקומיט ההורה). אם היא לא מראה את הבאג שם, אפס באתר החי לא מוכיח כלום. בתיקון של 6.10 הגרסה הישנה הראתה 473 אירועי scroll ב-4 שניות.
7. **איזה פרויקט Vercel מגיש**: אפשר להשוות `etag` של `https://yakircohen.com` ל-`https://yakircohen-site.vercel.app` (נמדד ב-2.10.2026 שהפרויקט `yakircohen-site` הוא זה שמגיש ייצור). הוא מסמן ששני הכתובות מגישות אותו build, אבל לא מוכיח sha.
8. **סטטוס CI**: אומרים "ירוק" רק אם קראו את ה-check-run של הקומיט הדחוף. `gh` לא מותקן על ה-Mac הזה. אם הבעלים מחובר ל-GitHub בדפדפן אפשר לפתוח את דף הקומיט `https://github.com/callwebboss-bit/yakircohen.com/commit/<sha>` ולקרוא את הסטטוס משם. **לא שולפים טוקן מ-keychain כדי לקרוא את ה-API.** אם אי אפשר לקרוא, כותבים "CI לא נבדק". Vercel מפרס בלי קשר ל-CI.

## 6. הדוח לבעלים

בעברית, בקצרה, עם עדות לכל טענה: sha שנדחף, השערים שרצו ומה יצא, השערים שלא רצו, מה הוכח חי (הסמן וכמה פעמים נמצא, המדידות), ומה לא נבדק. מה שלא אומת נכתב כ"לא נבדק" ולא נעלם.

אם הגרסה החיה שבורה: מציעים `git revert <sha>` ב-worktree, מריצים אותו דרך אותם שערים, ושואלים את הבעלים לפני הדחיפה.
